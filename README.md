# docsearch — поиск по архиву документов на сетевой папке

Инструмент для ПТО и делопроизводства: находит письма, акты, протоколы,
ведомости и чертежи в сетевой папке по смыслу запроса, а не по точному
имени файла.

Файлы остаются там, где лежат. Ничего не перемещается, не копируется и
не переименовывается — строится только индекс рядом.

## Что уже работает

- Индексация `.docx`, `.xlsx`, `.pdf`, `.txt`, `.csv`, `.rtf`, `.msg`
- `.doc` и `.xls` читаются через установленный Office отдельной командой
- `.dwg`, изображения и архивы — по имени файла и пути
- Морфология русского языка: «поставка щебня» находит «поставки щебня»
- Точная фраза в кавычках
- Атрибуты документа: тип, номер, дата, контрагент, шифр объекта
- Организация берётся из шапки документа, своя не считается контрагентом
- Ручная правка атрибутов в интерфейсе: она сильнее разбора и не теряется
- Кнопка «Проверить папку» и очередь новых документов на проверку
- 33 типа документов делопроизводства ПТО, опознаются по леммам
- Фильтры по типу, расширению, диапазону дат, корню
- Фрагмент текста вокруг совпадения с подсветкой
- Инкрементальное обновление: повторный прогон трогает только изменившееся
- OCR сканов через Tesseract: отдельным шагом, с продолжением после остановки
- Веб-интерфейс: поиск плюс отбор по разделу, категории, организации, году
- Генератор исходящих писем: автонумерация из архива, бланк, .docx
- Интерактивный поиск в консоли с открытием документа из выдачи
- Отчёт `problems`: что не попало в поиск и почему
- Корзина NAS (`#recycle`) и кэш эскизов (`@eaDir`) не индексируются

## Установка

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

## Использование

Создать конфиг для своего архива:

```bash
.venv/Scripts/docsearch.exe init --root "//server/share/ПТО" --db index.db -o config.local.yaml
```

Файл пишется в UTF-8, обратные слэши из адресной строки проводника
приводятся к прямым. Метка по умолчанию — имя последней папки в пути.

Дальше:

```bash
.venv/Scripts/python.exe -m docsearch.cli survey
```

Разведка: сколько файлов, в каких форматах, какая доля PDF без
текстового слоя. Запускать первым — она показывает объём работ до того,
как что-то индексировать.

```bash
.venv/Scripts/python.exe -m docsearch.cli index
```

```bash
.venv/Scripts/python.exe -m docsearch.cli search "радиаторы" --type письмо --org маренго --from 2025-01-01
```

Ежедневный способ искать — интерактивный режим: словари морфологии
грузятся один раз, дальше запрос за запросом.

```bash
.venv/Scripts/docsearch.exe -c config.local.yaml shell
```

Внутри: слова — искать, `о3` — открыть третий документ в его программе,
`т3` — показать текст, `п3` — показать файл в проводнике, `ещё` —
следующая страница выдачи, `в` — выход.

Выдача всегда подписана: сколько найдено всего и какие номера показаны.
Без этой строки человек видит десять результатов и решает, что документов
в архиве десять.
Команды понимают и латиницу, и кириллицу: раскладку ради одной буквы
никто переключать не станет.

В Windows есть обёртка `ds.cmd` — `ds` открывает интерактивный поиск,
`ds "запрос"` ищет разово.

```bash
.venv/Scripts/python.exe -m docsearch.cli stats
```

```bash
.venv/Scripts/python.exe -m docsearch.cli problems
```

`problems` — главный отчёт при обкатке на реальном архиве: какая доля
документов попала в поиск с текстом, какие файлы не открылись и с какой
ошибкой, что ушло в очередь на OCR.

```bash
.venv/Scripts/python.exe -m docsearch.cli sniff --status error -v
```

`sniff` смотрит на первые байты файлов и говорит, чем они являются на
самом деле. В архиве регулярно встречаются файлы, переименованные
вручную: расширение `.pdf`, а внутри ZIP или старый Word. По ошибке
разбора это не видно, по сигнатуре — сразу.

## Распознавание сканов

Нужен [Tesseract](https://github.com/UB-Mannheim/tesseract/wiki), при
установке обязательно отметить компонент **Cyrillic** — без него на
русских документах получится бессмысленная латиница. Путь можно задать
переменной `TESSERACT_CMD`, если Tesseract стоит не в обычном месте.

```bash
.venv/Scripts/python.exe -m docsearch.cli ocr -n 50
```

Распознавание идёт отдельно от индексации: оно на порядки медленнее, и
его нужно уметь прервать и продолжить. Индексатор только помечает файлы,
которым нужен OCR, а `ocr` разбирает очередь — от мелких файлов к
крупным, чтобы результат был виден с первых минут. Прерванный прогон
продолжается с того же места: уже распознанное не переделывается.

Распознаётся PDF постранично, картинки целиком и `.docx` со вставленными
сканами — в делопроизводстве скан часто вклеивают прямо в Word.

По умолчанию язык — только русский. С `rus+eng` Tesseract на неотличимых
по начертанию буквах выбирает латиницу, и номер письма `РТП-161`
превращается в `PIIT-161`, после чего перестаёт находиться. Остатки такой
подмены чинятся автоматически: слово, где кириллица преобладает, а вся
латиница в нём — двойники, приводится к кириллице.

Сравнить настройки на одном документе:

```bash
.venv/Scripts/python.exe -m docsearch.cli ocr --id 902 --lang rus --dpi 400
```

```bash
.venv/Scripts/python.exe -m docsearch.cli text "огнезащита"
```

`text` показывает документ так, как его видит поиск. Это главный способ
оценить качество распознавания: если текст читаемый — OCR отработал.

Флаг `--retry-failed` возвращает в очередь сканы, на которых
распознавание сорвалось — например, чтобы повторить их с большим `--dpi`.

## Старые форматы: .doc и .xls

Это форматы девяностых, и открыть их умеет только сам Office. Без них из
поиска выпадают целые подрядчики: переписка с ними лежит в `.doc`, а
значит ни текста, ни организации, ни договора у таких писем нет.

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml legacy --ext .doc
```

Индексация такие файлы только помечает — читает их отдельная команда,
как и распознавание сканов. Конвертация идёт партиями: запуск Word
занимает секунды, а перегонка файла доли секунды, поэтому на партию
приложение поднимается один раз. Отдельной библиотеки не нужно, COM
вызывается через PowerShell.

Office должен стоять на той машине, где идёт индексация. Прогон
прерываемый, повтор продолжает с места остановки.

## Пересчёт атрибутов

Правила извлечения типа, даты и контрагента меняются чаще, чем сам архив.
Пересчитать их по уже сохранённому тексту — минуты, и распознанные сканы
при этом не теряются:

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml reparse
```

Файлы не открываются вообще, к сетевой папке обращения нет. Полная
переиндексация с `--force` нужна только когда изменился разбор самих
файлов — а она стирает результаты OCR и требует прогнать распознавание
заново.

## Веб-интерфейс

В Windows проще всего дважды щёлкнуть по `start.cmd` в папке проекта —
он поднимает приложение с конфигом `config.server.yaml`. Это же нужно
сделать после перезагрузки компьютера: приложение не служба и само не
запускается.

То же самое командой:

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml serve
```

При запуске выводятся все адреса, по которым приложение открывается —
свой и сетевые. Коллегам нужен тот, что начинается с `192.168`.

Дальше все открывают в браузере `http://адрес-этого-компьютера:8000/` —
устанавливать коллегам ничего не нужно. Слева отбор по категории
документа, организации, году и формату; счётчики пересчитываются под
текущий запрос, поэтому пустых категорий в панели не бывает.

Категорию можно выбрать и без поискового запроса — это просмотр архива,
а не поиск.

Файл отдаёт само приложение: ссылка `file://` из веб-страницы не
откроется, браузеры это запрещают. PDF и картинки показываются прямо в
браузере, остальное скачивается; рядом есть кнопка «Скопировать путь»,
чтобы вставить сетевой путь в проводник.

Выбранные фильтры живут в адресной строке, так что ссылку на конкретную
выборку можно переслать коллеге.

## Ручная правка атрибутов

Автоматический разбор ошибается: организация написана не так, категория
не та, дата взялась из соседней строки. В карточке документа поля можно
исправить руками — кнопка «Карточка и текст» в выдаче.

Правка хранится отдельно от разобранных значений и **привязана к пути
файла, а не к номеру документа**. Поэтому она переживает и пересчёт
атрибутов, и полную переиндексацию, и пересоздание базы с нуля. Поля,
которых человек не касался, продолжают разбираться автоматически.
Кнопка «Вернуть автоматические» снимает правку.

Варианты написания одной организации, которые правилами не свести,
задаются в конфиге:

```yaml
  organization_aliases:
    ООО «СКМ»:
      - СК М
      - СКМ-Строй
```

## Новые документы

Кнопка «Проверить папку» обходит архив и добавляет появившиеся файлы.
Обход инкрементальный: неизменившееся не перечитывается, поэтому по
архиву в 45 тысяч файлов это минуты.

Кнопка «Новые» показывает недавно добавленное — очередь на проверку.
У нового документа атрибуты разобраны машиной, и человеку стоит на них
взглянуть, пока он помнит, что это за документ. Проверенные помечаются.

## Разделы архива

Тридцать три типа документов хороши для точного фильтра, но бесполезны,
когда в выдаче вперемешку лежат двухсотстраничный альбом РД и скан
письма на одну страницу. Поверх типов есть крупная группировка:
переписка, исполнительная, проектная документация, качество материалов,
договоры и финансы, организационные, фотоматериалы, прочее.

Раздел определяется по типу документа, если он известен; иначе по пути;
иначе по расширению. Письмо, лежащее в папке проекта, остаётся
перепиской. Структура папок у всех своя, поэтому свои правила задаются
в конфиге и побеждают встроенные:

```yaml
  sections:
    охрана труда:
      - Охрана труда
      - ОТ и ТБ
```

## Исходящие письма

Генератор собирает письмо в `.docx`: шапка организации из конфига,
следующий свободный номер, адресат, тема, ссылка на входящее, подпись.

Номер берётся **из самого архива**: максимум по вашему префиксу плюс
один. Считается он по папке исходящих, заданной в `number_folder` — по
всему архиву в выборку попадает посторонняя нумерация. Одиночное
значение, оторвавшееся от остальных, отбрасывается: скан с приписанной
при распознавании цифрой задирал счётчик на порядок. Отдельный журнал исходящих никто вести не станет, а письма в
папке — это и есть журнал. Адресаты подсказываются из тех, с кем уже
переписывались. Кнопка «Ответить» в выдаче подставляет ссылку «На №» и
организацию из найденного письма.

Бланк заполняется в конфиге:

```yaml
letterhead:
  name: "ООО «ФБ-СТРОЙ»"
  legal_address: "141014, Московская обл., г. Мытищи, ул. Веры Волошиной, д. 14"
  inn: "5029172308"
  kpp: "502901001"
  phone: "8(499)649-00-50"
  email: "info@fbstroy.ru"
  signer_position: "Начальник ПТО"
  signer_name: "Иноземцев Д. А."
  number_prefix: "РТП"
```

### Текст письма

Абзацы по умолчанию обычные. Нумерованный список включается
переключателем под полем текста — тогда каждая строка становится
пунктом. Преамбула в нумерацию не попадает.

### Преамбула

Первый абзац письма повторяется слово в слово, меняются только
организация и договор. Он задан шаблоном:

```yaml
letterhead:
  object: "«Жилой дом по адресу: Тайнинская ул., вл.16, корп. 3»"
  intro: >-
    Между {{recipient_org}} и {{own_org}} заключен договор подряда
    {{contract}} на выполнение подрядных работ по объекту строительства:
    {{object}}.
```

Наименование объекта в письмах одно и то же и занимает полстраницы,
поэтому оно отдельным полем. Незаполненные поля не оставляют следов:
висящего двоеточия в отправленном письме быть не должно.

В форме преамбула подставляется сама и остаётся правимой: если её
изменили руками, подстановка больше не перезаписывает. В бланке под неё
можно отвести отдельное место `{{intro}}`; если его нет, она становится
первым абзацем текста.

### Свой бланк

Программная вёрстка не похожа на то, что уходит из компании на самом
деле. Сделайте шаблон из любого отправленного письма — содержание
выбросится, вёрстка с логотипом останется:

```bash
.venv/Scripts/python.exe tools/make_template.py "Исх. РТП-1335.docx" templates/письмо.docx
```

Старый `.doc` сначала пересохраните в `.docx`, Word умеет это сам. Путь
к шаблону пропишите в `letterhead.template`.

Посмотреть, что в готовом шаблоне размечено:

```bash
.venv/Scripts/python.exe tools/make_template.py --show templates/письмо.docx
```

Нумерация абзацев из бланка снимается: в исходном письме мог быть
нумерованный список, и его разметка остаётся в пустых абзацах — Word
исправно рисует «1.» и «2.» на пустом месте. Нумерация задаётся в форме,
а не в бланке. Шаблон правится в Word как
обычный документ — подстановки вида `{{subject}}` это просто текст.

Шаблоны лежат в `templates/` и **в репозиторий не попадают**: в бланке
логотип и реквизиты организации.

### Адресаты

Должность и фамилию адресата брать неоткуда — кроме как из прошлых
писем. Блок «кому» в исходящем это готовая карточка:

```
Генеральному директору
ООО «Мосренстрой-6»
Севрюкову Е.В.
```

Справочник собирается по переписке сам — и по адресатам, и по
отправителям. Входящие письма дают контрагентов, которым мы ни разу не
писали: без них в справочнике не было бы целых организаций. Подпись
отправителя приводится к виду адресата: «Генеральный директор
А.М. Лукашин» становится «Генеральному директору Лукашину А.М.», иначе
сгенерированное письмо уйдёт с ошибкой в падеже.

Побеждает самое свежее письмо —
должности меняются. У организации бывает несколько адресатов, поэтому
ключ — пара «организация и человек».

Написания сводятся: «ПД-Проект» и «ПД-ПРОЕКТ», «Проф/Люкс» и «ПрофЛюкс»,
«СК АВАНГАРД» и «СК-Авангард» — одна организация, регистр и пунктуация
значения не имеют. Фамилия приводится к именительному падежу, поэтому
«Глоба А.В.» и «Глобу А.В.» — один человек. Своя организация в адресаты
не попадает: во входящих письмах адресат — мы сами.

В форме одно поле «Кому»: печатаете фамилию, имя или организацию — в
любом порядке, — и видите подходящих. Падежи учитываются: в письме стоит
«Вороновой», ищется и по «Воронова». Выбрали — должность, организация, договор и обращение подставились.
Обращение берётся из прошлых писем: имя и отчество получателя больше
взять неоткуда, в блоке «кому» стоят только фамилия и инициалы. Заодно
сохраняется род — «Уважаемая Марина Александровна».

Договор тоже берётся из прошлых писем: основание в первом абзаце
повторяется из раза в раз.

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml contacts --rebuild
```

Отчёт показывает, насколько справочник заполнен — у скольких адресатов
есть фамилия, обращение и договор. Посмотреть именно тех, у кого чего-то
нет:

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml contacts --missing greeting
```

Файл называется так же, как письма в вашей папке исходящих:
`Исх. РТП-1338 ПКС-Инжиниринг (ответ УКМ-299).docx` — номер, с кем
переписка, в скобках о чём. Даты в имени нет: она и так в номере по
порядку.

Результат — `.docx`, а не PDF: письмо почти всегда правят перед
отправкой, потом печатают, подписывают и сканируют обратно в архив.
Файл **скачивается**, в сетевую папку ничего не пишется — куда положить
письмо, решает человек.

## Демо-данные

Реальные документы в репозиторий не попадают. Для проверки и показа есть
генератор синтетического архива:

```bash
.venv/Scripts/python.exe tools/make_sample.py
```

Он создаёт `sample/` со ста пятьюдесятью файлами: письма, акты,
протоколы, ведомости, чертежи и несколько PDF без текстового слоя.

## Как устроено

```
сетевая папка (источник правды)
      ↓  walker      обход с исключениями из конфига
      ↓  extract     текст по типу файла
      ↓  textnorm    убрать неразрывные пробелы и мягкие переносы
      ↓  meta        тип, номер, дата, контрагент, шифр
      ↓  morph       леммы для морфологического поиска
   SQLite + FTS5
      ↓  search      запрос → леммы → FTS5 MATCH → bm25
      ↓  snippet     фрагмент вокруг совпадения
```

Хранилище — один файл SQLite. Пишет только индексатор, читают все.
Отдельный сервер БД не нужен, бэкап — копирование файла.

В FTS5 три колонки: `name`, `body` (исходный текст, из него берётся
фрагмент) и `lemmas` (тот же текст в начальных формах — по нему идёт
поиск). Имя файла весит в ранжировании больше текста.

## Свой конфиг

`config.yaml` в репозитории — образец с демо-данными. Рабочие настройки
держатся отдельно, чтобы имена серверов и папок не попадали в git:

```bash
copy config.yaml config.local.yaml
```

```bash
.venv/Scripts/docsearch.exe -c config.local.yaml survey
```

Относительные пути в конфиге считаются от папки самого конфига, поэтому
репозиторий переносится между машинами без правки путей.

Сетевую папку писать в одинарных кавычках:

```yaml
roots:
  - label: "ПТО"
    path: '//server/share/ПТО'
```

Обратные слэши тоже принимаются — путь можно скопировать прямо из
адресной строки проводника. А вот двойные кавычки с обратными слэшами
YAML не разберёт: в них слэш считается экранированием.

## Ночной прогон по всему архиву

Большой архив индексируют и распознают ночью, отдельным конфигом со
своей базой — тогда уже работающий индекс не пострадает, если прогон
сорвётся.

```bash
.venv/Scripts/docsearch.exe -c config.server.yaml index > night.log 2>&1 && .venv/Scripts/docsearch.exe -c config.server.yaml ocr --ext .pdf >> night.log 2>&1
```

Прогресс с возвратом каретки при перенаправлении в файл не печатается,
так что лог остаётся читаемым. Прогон прерываемый: если ночи не хватило,
утром та же команда продолжит с места остановки.

`--ext .pdf` здесь принципиален. Изображения тоже помечаются как
требующие распознавания, но фотографии объекта — это тысячи файлов, на
которых нечего искать, а времени они стоят часов.

## Перенос на машину без интернета

Рабочие компьютеры часто отрезаны от pypi и не дают прав администратора.
Комплект для такого случая собирается на машине с сетью:

```bash
git bundle create docsearch.bundle --all
```

```bash
.venv/Scripts/python.exe -m pip download -r requirements.txt -r requirements-dev.txt -d wheels
```

На целевой машине — установка без единого сетевого запроса:

```bash
.venv/Scripts/python.exe -m pip install --no-index --find-links wheels -r requirements.txt
```

Папку `.venv` переносить нельзя: в ней абсолютные пути. Окружение
создаётся на месте заново.
